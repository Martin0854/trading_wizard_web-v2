# Feature Specification: Trading Wizard Web Interface

**Feature Branch**: `001-trading-wizard-ui`
**Created**: 2026-01-24
**Status**: Draft
**Input**: 두 개의 독립적인 웹 인터페이스 설계 - Daily Focus Wizard (매수 추천)와 My Portfolio Wizard (포트폴리오 관리)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Daily Focus Wizard 매수 추천 조회 (Priority: P1)

사용자가 Daily Focus Wizard에 접속하여 오늘의 매수 추천 종목 목록을 확인합니다. 볼린저 밴드 스퀴즈 전략 기반으로 분석된 KOSPI Top 100 종목 중 매수 신호가 발생한 종목들이 신뢰도 점수 순으로 정렬되어 표시됩니다.

**Why this priority**: 핵심 기능으로, 사용자가 가장 먼저 필요로 하는 매수 종목 추천 정보를 제공합니다.

**Independent Test**: Daily Focus Wizard 페이지에 접속하면 매수 추천 종목 목록이 표시되고, 각 종목의 신뢰도 점수와 관련 지표를 확인할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 Daily Focus Wizard 페이지에 접속했을 때, **When** 페이지가 로드되면, **Then** KOSPI Top 100 종목 중 매수 신호가 발생한 종목 목록이 신뢰도 점수 내림차순으로 표시됩니다.
2. **Given** 매수 추천 목록이 표시된 상태에서, **When** 사용자가 특정 종목을 선택하면, **Then** 해당 종목의 상세 분석 정보(볼린저 밴드, RSI, MACD, 거래량 비율 등)가 표시됩니다.
3. **Given** 매수 추천 종목이 없을 때, **When** 페이지가 로드되면, **Then** "오늘은 매수 추천 종목이 없습니다" 메시지가 표시됩니다.

---

### User Story 2 - My Portfolio Wizard 보유 종목 관리 (Priority: P1)

사용자가 My Portfolio Wizard에서 자신이 매수한 종목을 등록하고, 매수가와 수량을 기록합니다. 등록된 종목에 대해 현재 수익률을 실시간으로 확인할 수 있습니다.

**Why this priority**: 포트폴리오 관리의 핵심 기능으로, 사용자가 자신의 투자 현황을 파악하는 데 필수적입니다.

**Independent Test**: My Portfolio Wizard에서 종목을 추가하고, 매수가/수량을 입력한 후 수익률이 계산되어 표시되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 My Portfolio Wizard에 접속했을 때, **When** 새 종목 추가를 선택하면, **Then** 종목 검색, 매수가, 매수 수량, 매수일을 입력할 수 있는 양식이 표시됩니다.
2. **Given** 포트폴리오에 종목이 등록된 상태에서, **When** 페이지가 로드되면, **Then** 각 종목의 매수가, 현재가, 수익률(%), 평가금액이 표시됩니다.
3. **Given** 포트폴리오에 종목이 등록된 상태에서, **When** 사용자가 종목을 매도 처리하면, **Then** 매도가와 매도일을 입력하고 해당 거래가 매도 완료 상태로 기록됩니다.

---

### User Story 3 - My Portfolio Wizard 매도 추천 확인 (Priority: P2)

사용자가 보유 중인 종목에 대해 매도 추천 신호를 확인합니다. 손절매(-4.5%), 익절매(+12%), 볼린저 중심선 이탈 등의 조건에 따라 매도 추천이 표시됩니다.

**Why this priority**: 매도 타이밍 결정을 지원하는 기능으로, 손실 최소화와 수익 실현에 중요합니다.

**Independent Test**: 보유 종목 중 매도 조건을 충족하는 종목에 매도 추천 신호가 표시되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 보유 종목 중 손실률이 -4.5% 이하인 종목이 있을 때, **When** 포트폴리오를 조회하면, **Then** 해당 종목에 "손절매 추천" 신호가 표시됩니다.
2. **Given** 보유 종목 중 수익률이 +12% 이상인 종목이 있을 때, **When** 포트폴리오를 조회하면, **Then** 해당 종목에 "익절매 추천" 신호가 표시됩니다.
3. **Given** 보유 종목 중 현재가가 볼린저 중심선 아래로 하락한 종목이 있을 때, **When** 포트폴리오를 조회하면, **Then** 해당 종목에 "추세 이탈" 신호가 표시됩니다.

---

### User Story 4 - Daily Focus Wizard 전략 파라미터 설정 (Priority: P2)

사용자가 볼린저 밴드 스퀴즈 전략의 파라미터를 자신의 투자 스타일에 맞게 조정합니다. 변경된 설정은 저장되어 다음 접속 시에도 유지됩니다.

**Why this priority**: 고급 사용자의 맞춤형 전략 활용을 지원하는 기능입니다.

**Independent Test**: 전략 파라미터를 변경하고 저장한 후, 변경된 파라미터로 매수 추천이 재계산되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 설정 페이지에 접속했을 때, **When** 볼린저 밴드 기간을 15일로 변경하고 저장하면, **Then** 변경된 설정이 저장되고 매수 추천이 새 파라미터로 계산됩니다.
2. **Given** 설정 페이지에서, **When** 신뢰도 임계값을 60점으로 변경하면, **Then** 60점 미만의 종목은 매수 추천 목록에서 제외됩니다.
3. **Given** 설정을 변경한 후, **When** 초기화 버튼을 누르면, **Then** 모든 파라미터가 기본값으로 복원됩니다.

---

### User Story 5 - My Portfolio Wizard 전략 파라미터 설정 (Priority: P2)

사용자가 매도 전략의 파라미터(손절매 비율, 익절매 비율 등)를 조정합니다. 각 Wizard의 설정은 독립적으로 관리됩니다.

**Why this priority**: 개인 투자 성향에 맞는 리스크 관리 설정을 지원합니다.

**Independent Test**: 손절매 비율을 변경한 후, 해당 비율에 따라 매도 추천이 재계산되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 My Portfolio 설정 페이지에서, **When** 손절매 비율을 -5%로 변경하면, **Then** 변경된 비율에 따라 손절매 추천이 재계산됩니다.
2. **Given** 설정 페이지에서, **When** 익절매 비율을 +15%로 변경하면, **Then** 15% 이상 수익 종목에 익절매 추천이 표시됩니다.
3. **Given** 중심선 이탈 매도 옵션이 비활성화된 상태에서, **When** 보유 종목이 중심선을 이탈해도, **Then** 추세 이탈 신호가 표시되지 않습니다.

---

### User Story 6 - 포트폴리오 수익률 요약 대시보드 (Priority: P3)

사용자가 전체 포트폴리오의 수익률 현황을 한눈에 파악할 수 있는 요약 정보를 확인합니다.

**Why this priority**: 투자 성과의 전체 그림을 제공하는 보조 기능입니다.

**Independent Test**: 포트폴리오에 여러 종목이 등록된 상태에서 전체 평가금액과 총 수익률이 정확히 계산되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 포트폴리오에 종목들이 등록된 상태에서, **When** 대시보드를 조회하면, **Then** 총 투자금액, 현재 평가금액, 전체 수익률(%)이 표시됩니다.
2. **Given** 대시보드에서, **When** 종목별 비중을 확인하면, **Then** 각 종목이 전체 포트폴리오에서 차지하는 비율이 표시됩니다.

---

### Edge Cases

- **종목 데이터를 가져올 수 없는 경우**: 오류 메시지만 표시하고 재시도하지 않음. 사용자에게 네트워크 상태 확인 또는 나중에 다시 시도하라는 안내 제공.
- **동일 종목을 여러 번 매수한 경우**: 가중 평균 매수가로 계산. 공식: `avgPrice = Σ(price × qty) / Σqty`
- **상장폐지된 종목이 포트폴리오에 있는 경우**: MVP 범위 외. 향후 버전에서 "거래 중지" 상태 표시 및 수동 정리 기능 추가 예정.
- **분할/병합된 종목의 가격 조정**: MVP 범위 외. 사용자가 수동으로 포지션을 수정해야 함.
- **비정상적인 파라미터 값 입력**: data-model.md에 정의된 범위를 벗어나는 값은 입력 시점에 거부되며, 유효한 범위 안내 메시지 표시.

## Requirements *(mandatory)*

### Functional Requirements

**Daily Focus Wizard**

- **FR-001**: 시스템은 KOSPI Top 100 종목의 일일 주가 데이터를 조회할 수 있어야 합니다.
- **FR-002**: 시스템은 볼린저 밴드(기간, 표준편차 배수), BB Width, RSI, MACD, 거래량 비율 지표를 계산해야 합니다.
- **FR-003**: 시스템은 볼린저 밴드 스퀴즈 돌파 조건(가격 돌파 AND 스퀴즈/밴드 확장)을 충족하는 종목을 식별해야 합니다.
- **FR-004**: 시스템은 각 매수 신호 종목에 대해 신뢰도 점수(0-100점)를 계산해야 합니다.
- **FR-005**: 시스템은 신뢰도 임계값 이상의 종목만 매수 추천 목록에 표시해야 합니다.
- **FR-006**: 시스템은 매수 추천 목록을 신뢰도 점수 순으로 정렬하여 표시해야 합니다.
- **FR-007**: 사용자는 전략 파라미터를 조회하고 수정할 수 있어야 합니다.
- **FR-008**: 변경된 전략 파라미터는 저장되어 다음 세션에서도 유지되어야 합니다.

**My Portfolio Wizard**

- **FR-009**: 사용자는 종목을 검색하여 포트폴리오에 추가할 수 있어야 합니다.
- **FR-010**: 사용자는 각 종목에 대해 매수가, 매수 수량, 매수일을 기록할 수 있어야 합니다.
- **FR-011**: 시스템은 각 보유 종목의 현재가를 조회하여 수익률을 계산해야 합니다.
- **FR-012**: 사용자는 보유 종목을 매도 처리하고 매도가, 매도일을 기록할 수 있어야 합니다.
- **FR-013**: 시스템은 손절매 조건(-4.5% 기본)을 충족하는 보유 종목에 손절매 추천 신호를 표시해야 합니다.
- **FR-014**: 시스템은 익절매 조건(+12% 기본)을 충족하는 보유 종목에 익절매 추천 신호를 표시해야 합니다.
- **FR-015**: 시스템은 볼린저 중심선 이탈 종목에 추세 이탈 신호를 표시해야 합니다 (설정 가능).
- **FR-016**: 사용자는 매도 전략 파라미터를 조회하고 수정할 수 있어야 합니다.
- **FR-017**: 시스템은 동일 종목 복수 매수 시 가중 평균 매수가를 자동 계산해야 합니다. 공식: `avgPrice = Σ(price × qty) / Σqty`

**공통**

- **FR-018**: 두 Wizard는 독립적인 웹 인터페이스로 동작하며, 별도의 설정을 관리해야 합니다. 설정은 암호화된 blob 형태로 서버에 저장됩니다 (파일 시스템 설정 파일 아님).
- **FR-019**: 시스템은 파라미터 입력값에 대한 유효성 검사를 수행해야 합니다. 유효 범위는 data-model.md의 Validation Rules 섹션 참조.
- **FR-020**: 시스템은 데이터 조회 실패 시 사용자에게 적절한 오류 메시지를 표시해야 합니다.
- **FR-021**: 시스템은 사용자 데이터를 개인 비밀번호 또는 PEM 파일 기반으로 클라이언트에서 암호화하여 서버 DB에 저장해야 합니다. 서버는 암호화된 blob만 저장하며, 복호화 키를 보유하지 않습니다.
- **FR-022**: 시스템은 비밀번호/PEM 파일에서 파생된 해시를 사용자 식별자로 사용해야 합니다. 별도의 회원가입 절차 없이 동일한 비밀번호/PEM으로 어느 기기에서든 데이터에 접근 가능합니다.

### Parallel Development Requirements (병렬 개발 요구사항)

두 Wizard를 독립적인 개발 세션에서 병렬로 개발할 수 있도록 다음 요구사항을 충족해야 합니다:

**디렉토리 구조 분리**

- **PD-001**: Daily Focus Wizard와 My Portfolio Wizard는 완전히 분리된 디렉토리 구조를 가져야 합니다.
- **PD-002**: 각 Wizard는 자체 컴포넌트, 페이지, 스타일, 설정 파일을 독립적으로 관리해야 합니다.
- **PD-003**: 공유 코드(기술적 지표 계산, 주가 데이터 조회 등)는 별도의 공통 라이브러리로 분리해야 합니다.

**인터페이스 계약 (Interface Contracts)**

- **PD-004**: 공유 라이브러리의 인터페이스(함수 시그니처, 데이터 타입)는 개발 착수 전 확정되어야 합니다.
- **PD-005**: 각 Wizard가 사용하는 데이터 모델(Stock, DailyFocusSettings, PortfolioSettings 등)의 스키마는 사전 정의되어야 합니다.
- **PD-006**: API 엔드포인트 명세(입출력 형식)가 개발 전 문서화되어야 합니다.

**독립 실행 환경**

- **PD-007**: 각 Wizard는 독립적으로 빌드 및 실행 가능해야 합니다.
- **PD-008**: 각 Wizard는 자체 개발 서버를 별도 포트에서 실행할 수 있어야 합니다.
- **PD-009**: 각 Wizard의 테스트는 다른 Wizard 코드에 의존하지 않고 독립 실행 가능해야 합니다.

**Git 브랜치 전략**

- **PD-010**: Daily Focus Wizard 개발은 `001-trading-wizard-ui/daily-focus` 브랜치에서 진행합니다.
- **PD-011**: My Portfolio Wizard 개발은 `001-trading-wizard-ui/my-portfolio` 브랜치에서 진행합니다.
- **PD-012**: 공유 라이브러리는 `001-trading-wizard-ui/shared-lib` 브랜치에서 선행 개발 후 두 브랜치에 병합합니다.

**통합 지점**

- **PD-013**: 두 Wizard 간 네비게이션(전환)은 단순 링크 방식으로 구현하여 의존성을 최소화합니다.
- **PD-014**: 최종 통합은 각 Wizard 개발 완료 후 메인 브랜치에서 진행합니다.

### Key Entities

- **Stock (종목)**: 종목코드, 종목명, 현재가, 기술적 지표 데이터 (볼린저 밴드, RSI, MACD, 거래량)
- **BuyRecommendation (매수 추천)**: 종목, 신뢰도 점수, 추천 사유, 생성일시
- **PortfolioPosition (포트폴리오 포지션)**: 종목, 매수가, 매수 수량, 매수일, 현재가, 수익률, 매도 상태
- **SellRecommendation (매도 추천)**: 포지션, 추천 유형 (손절/익절/추세이탈), 추천 사유

## Assumptions

- KOSPI Top 100 종목 목록은 사전에 정의되어 있으며, 주기적으로 업데이트됩니다.
- 주가 데이터는 yfinance (Yahoo Finance Python 라이브러리)를 통해 조회합니다. 한국 주식은 종목코드에 .KS(KOSPI) 또는 .KQ(KOSDAQ) 접미사를 사용합니다.
- 사용자별 포트폴리오 및 설정 데이터는 클라이언트에서 암호화된 후 서버 DB에 영구 저장됩니다. 서버는 복호화 키를 보유하지 않습니다.
- 거래량 비율 계산을 위한 20일 평균 거래량 데이터가 제공됩니다.
- 시스템은 장 운영 시간과 휴장일을 인지하고 적절히 처리합니다.
- 동일 종목 복수 매수 시 가중 평균(weighted average) 방식으로 평균 매수가를 계산합니다. 공식: `avgPrice = Σ(price × qty) / Σqty`
- 파라미터 설정은 각 Wizard별로 독립적인 설정 파일로 관리됩니다.
